# M06 · SELinux sur le serveur web
*Permis ou refusé ? · Famille MAC · niveau 3 (expert) · diapositive(s) 53 du cours UCUE-S5-4-1 · Modèles de contrôle d’accès*

## Le cas
Le serveur web Apache de TransLor est compromis. L’attaquant tente de lire le répertoire personnel de Marc, accessible par les droits Unix classiques.

## La question
**Que fait SELinux, en mode enforcing avec la politique par défaut ?**

## Les quatre réponses, une par une
- ❌ A. Il autorise : le processus est root  
  *Pourquoi non ?* Être root n’y change rien si le domaine n’a pas la permission : le MAC s’ajoute au DAC.
- ❌ B. Il autorise : c’est le propriétaire du répertoire  
  *Pourquoi non ?* La propriété relève du DAC ; le MAC reste prioritaire.
- ✅ **C. Il refuse : le domaine du processus n’a pas le type d’accès, même si les droits Unix le permettent**  
  *Bonne réponse.* SELinux est un MAC : chaque processus appartient à un domaine, et la politique liste précisément les types de fichiers accessibles. Un serveur web compromis reste confiné, même si les droits Unix (DAC) le permettaient.
- ❌ D. Il désactive Apache  
  *Pourquoi non ?* SELinux journalise et refuse l’accès, il n’arrête pas le service.

## À retenir
> MAC confine un processus compromis, même si le DAC l’autorise.

## Chez TransLor
Le MAC limite les dégâts lorsqu’une application exposée à Internet est compromise.

## Barème
Joueur actif : 3 points + la carte. Autres joueurs ayant la bonne réponse : +1 point.
